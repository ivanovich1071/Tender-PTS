# Tender-PTS

Отбор тендеров Республики Беларусь по профилю ООО «Промтехснаб».

Приложение само проходит белорусские площадки по номенклатуре компании,
отсеивает неактуальное и выкладывает оператору карточку лота: предмет закупки,
сроки, заказчика, документацию и чертежи, живые ссылки на процедуру. Решение об
участии принимает человек — система доводит только до оценки.

## Запуск

```bash
python -m app
```

Откроется браузер на `http://127.0.0.1:8770`. С флагом `--window` то же самое
живёт в отдельном окне (нужен `pywebview`). Наружу приложение не слушает.

Первый запуск:

```bash
python -m venv .venv
.venv/Scripts/python -m pip install -r requirements.txt
.venv/Scripts/python -m app
```

## Как это работает

**Источник — ГИАС (`gias.by`).** У сайта есть внутренний JSON API без
авторизации: поиск по закупкам и карточка с лотами, сроками и списком
приложенных файлов. Официальной документации нет, контракт снят с сетевых
запросов самого сайта, поэтому форма ответа проверяется явно и при расхождении
сбор падает громко — см. `app/sources/gias.py`.

**Отбор идёт по лотам, а не по названию закупки.** Самые крупные лоты названы
«Аукцион» или «Закупка из одного источника», а деталь видна только внутри:
«Объемная штамповка из стали "Вал шестерня" №97». Дополнительный сигнал — имена
приложенных файлов: площадка переименовывает их в транслит
(`val-shesternya-97.jpg`), и по имени видно деталь, не открывая файл.

**Актуальность — жёсткий фильтр.** Лот со сроком подачи меньше двух рабочих
дней в список не попадает вообще. Рабочие дни считаются по календарю РБ:
праздники и переносы задаются в настройках текстом, потому что объявляются
постановлением на каждый год.

**Заказчики под наблюдением.** 19 крупных предприятий машиностроения,
металлообработки, химии и горнодобычи — от Амкодора и БМЗ до Беларуськалия и
Нафтана. Их закупки называются «Аукцион», деталь видна только внутри лота,
поэтому лот такого заказчика доходит до второго уровня отбора и без совпадения
по словам. Раньше он попадал в список сразу — и список наполнялся огнеупорными
смесями, контакторами и счётчиками воды: заказчик правильный, предмет чужой.

**Второй уровень отбора — модель.** Правила ловят слово, модель решает по
смыслу. «Поддон деревянный» и «поддон печи закалочной» пишутся одинаково, а
нужен только второй; «форсунка ТНВД» — не наша, «форсунка закалочной камеры» —
наша. Искать точное совпадение с названием чертежа тоже бесполезно: часть
деталей повторяется из тендера в тендер, часть выпадает раз в год. Поэтому
модели даётся не словарь, а признак производства из профиля — ПТС делает
металлические детали по чертежу — и вопрос к ней один: может ли завод это
изготовить.

Идёт через OpenRouter, ключ вводится в настройках приложения и в git не
попадает; в журнале маскируется, как пароль прокси. Модель выбирается там же,
список бесплатных подтягивается с самой площадки — набор меняется чаще, чем
выходят наши версии. Лоты уходят пачками по 20, вердикт кладётся в кэш по
содержанию лота (заказчик + название + ОКПБ), поэтому повторяющаяся деталь
второй раз не стоит ни запроса. **Ключа нет — сбор идёт на правилах**, лоты
помечаются «моделью не проверено», причина уходит в журнал.

**Список чистится руками, и это запоминается.** У каждой строки плашка выбора,
над списком — «мимо профиля», «вернуть в профиль» и «удалить». Отсев модели и
ручные пометки живут на отдельной вкладке «Мимо профиля»: ничего не исчезает
молча, ошибочный отсев возвращается одним нажатием. Удалённое не приходит
следующим прогоном. Каждое решение оператора уходит в следующий запрос к модели
как пример — на них она учится точнее, чем на любых придуманных правилах, и
расхождение «модель сказала мимо, оператор вернул» отдельной строкой пишется
в журнал.

**Документы качаются через сервер, а не браузером.** Браузер оператора ходит
напрямую и о прокси приложения не знает, поэтому ссылка «на площадке» упирается
в блокировку. Кнопка «скачать» тянет файл через тот прокси, который задан в
настройках, кладёт в `work/docs/` и дальше открывает уже локальную копию.
Скачиватель заходит как браузер — сначала карточка закупки, потом файл в той же
сессии с `Referer` — и **проверяет содержимое, а не код ответа**. Закрытая по
региону площадка отвечает HTTP 200 и своей главной страницей; раньше она молча
ложилась на диск под именем `.pdf`, оператор видел «скачан» и получал «Не
удалось загрузить PDF-документ». Теперь такой ответ на диск не попадает, а в
статусе файла написано, что вернулась страница, и какая именно.

**Журнал в файл.** Каждый запуск заводит файл в `work/logs/`: обстановка при
старте, каждый шаг сбора, итоги по площадкам, предупреждения, неудачные
загрузки. Приложение запускают там, где открыты площадки, а разбираются в
происходящем в другом месте — экран не перешлёшь, файл перешлёшь. Пароль от
прокси в журнал не попадает: `socks5://user:pass@host` пишется как
`socks5://***@host`.

Кнопка **«проверить площадки»** в настройках стучится во все четыре хоста и
пишет результат туда же — по нему сразу видно, запущено «изнутри» или снаружи.

## Что известно про доступ к площадкам

Замерено 20.08.2026 с адреса вне Беларуси:

| Хост | Что отдаёт | Вывод |
|---|---|---|
| `gias.by` | работает | данные и метаданные берутся без прокси |
| `goszakupki.by` | таймаут | файлы документации без прокси не скачать |
| `icetrade.by` | 403 на любой путь + неполная цепочка сертификата | нужен белорусский прокси |
| `zakupki.butb.by` | работает | площадка на JSF, источник отложен |

**ГИАС — это только бюджетная сфера.** Крупные заводы закупают за собственные
средства, а это icetrade. У БМЗ в ГИАС 100 закупок за шесть лет (тепловизоры,
дизтопливо), у Гомельского химического последняя — за 2023 год. Поэтому
icetrade для ПТС важнее ГИАС, и без прокси видна лишь часть рынка.

Насколько важнее — видно по двум процедурам, открытым 20.08.2026 и в ГИАС
отсутствующим: Гомельский химический завод покупал запчасти к насосу
АХ 200/150/400 на 827 040 BYN, БМЗ — мотор-редукторы «или аналог» с требованием
приложить чертёж. И то и другое — прямо профиль ПТС.

Проверка расширения словаря показала то же самое: из 43 формулировок
(«изготовление по чертежам», «дробилка запасные части», «горно-шахтное
оборудование» и прочие) 34 дали ноль актуальных лотов. Поток в ГИАС тонкий не
из-за узкого профиля, а по состоянию рынка.

## Структура

```
app/
  sources/gias.py   источник ГИАС: поиск, карточка, разбор
  profile.py        профиль компании, транслитерация
  matching.py       отбор по номенклатуре, поставка против работы
  judge.py          второй уровень: модель решает, профильный ли лот
  documents.py      скачивание документации с проверкой содержимого
  calendar_by.py    рабочие дни РБ, фильтр актуальности
  collector.py      сбор целиком
  store.py          SQLite
  server.py         HTTP, только 127.0.0.1
  web/              интерфейс без сборки
profile.json        номенклатура ПТС, стоп-слова, заказчики
recon/              разведка: скрипты и отчёт по рынку
tests/              проверки календаря, отбора, модели и загрузки файлов
```

## Профиль

`profile.json` — словарь предметной области, правится текстом. Собран по архиву
реальных заказов ПТС за 2024–2026 и выверен прогонами по ГИАС: одиночные слова
из имён чертежей («ступица», «шнек», «гребенка») в поиске по госзакупкам не
работают — тащат автозапчасти и бытовую технику, поэтому оставлены только
различающие словосочетания.

## icetrade

Разбор написан по настоящим страницам: они лежат в `tests/fixtures/icetrade` и
служат договором — если площадка сменит шаблон, тесты упадут там, а не в тишине
во время сбора. Что из разметки следует:

- поля карточки помечены классами `af-*`, значение всегда в `td.afv`;
- лоты приходят прямо в HTML — догружать их отдельным запросом не нужно;
- **документация открыта без регистрации**: ссылки вида
  `/auction/getFile/auction/{id}?f=detail&n={N}` работают незалогиненному;
- часть процедур по постановлению № 168 держит файлы на стороннем ЭТП
  `goszakupki.by`, и цены у них может не быть вовсе.

Поиск по слову на этой площадке слабый — он смотрит только краткое описание
закупки: запрос «шестерня» дал четыре результата, и все мимо (запчасти к
тракторам для птицефабрик). Поэтому обход идёт тремя проходами — по отраслям,
по заказчикам из списка наблюдения и по словам профиля, — а отбор делается по
лотам карточки, как и в ГИАС.

Единственное, чего снять не удалось, — **как площадка листает длинную выдачу**.
В образцах было четыре результата, вторая страница не понадобилась. Сейчас
пробуется `&page=N`, и если ничего нового не приходит, сбор пишет в
предупреждениях, что часть закупок пропущена.

Без белорусского прокси источник отвечает 403 — это не поломка, а гео-блокировка.
